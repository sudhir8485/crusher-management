## Remaining Work — Phased Plan

### Phase 1 — Quick Wins (1–2 sessions each)

#### 1a. Dead-Code Cleanup
**Why first:** Zero user-facing risk, improves schema clarity before anyone builds more on top of it.

- Write V35 migration: `DROP TABLE water_tanker_logs; DROP TABLE vehicle_daily_logs;`
- Write V36 migration: `ALTER TABLE trips DROP COLUMN one_time_customer_name, DROP COLUMN one_time_customer_phone, DROP COLUMN one_time_customer_addr, DROP COLUMN party_type;` — these columns are no longer written to (since V18 in 2024) and the party_type is always 'REGULAR' for all new records
- Remove `mode` column from `machine_work_logs` (superseded by `work_type_id` since V28) — add as part of V36 or its own V37
- Update `Trip.java` entity to remove the corresponding Java fields
- Verify: `flutter analyze`, `mvn compile`, confirm no references remain

**Risk:** Low. No UI or API code references these tables/columns in the current codebase.

---

#### 1b. Dashboard Charts
**Why:** Dashboard currently shows stats tiles but no visual trends. Rules.md describes it as a "highlights" screen with graphical elements.

- Add `fl_chart` to pubspec.yaml (the standard Flutter chart package; no new backend needed — `/api/dashboard` already returns the data)
- Add a bar chart for "Trips this week by day" using `todayTripCount` pattern
- Add a line chart or progress bar for diesel stock level vs. historical receipts
- Keep tiles as-is (they're good); charts go in a new section below

**Scope:** Frontend only, single screen, ~150 lines.

---

### Phase 2 — Print-Ready GST Invoice PDF

**Why:** Operationally important — DSP sends formal GST tax invoices to R.D. Samant. The current invoices_screen.dart has a detail dialog with all the data but no way to generate a print-ready document.

**What it needs:**
- A "Print Invoice" button in `_InvoiceDetailDialog` and `_JwDetailDialog`
- A PDF generator function (similar pattern to `reports_screen.dart`'s `_buildPdf()`) that produces:
  - DSP Construction letterhead (name, GSTIN, address)
  - Invoice number, date, supply date, PO number
  - Party name + GSTIN
  - Line items table (description, HSN/SAC, qty, rate, amount)
  - CGST / SGST / Grand Total
  - Footer: "Generated by DSP Site Manager"
- The `pdf` and `printing` packages are already in pubspec.yaml — no new dependencies needed
- Same for Job-Work invoices (separate template, or parameterized shared template)

**Scope:** Frontend only, new function in invoices_screen.dart, ~200 lines. No backend changes.

### Phase 3 — Remaining Polish (lower priority)

#### 3a. GST Invoice: Supply Date and PO No UI
Currently `supply_date` and `po_no` are stored in `gst_invoices` table but the create/edit form may not expose them (verify before building). If missing, add to the form — minimal effort.

#### 3b. Ledger / Accounts drill-through refinements
As usage reveals edge cases. No specific gap identified currently.

#### 3c. Machine Work — Customer Billing Status Flow
The PENDING → SET → GST invoice flow is implemented but the UX for setting the rate (⋮ → Edit) could be surfaced more prominently. Consider an inline "Set Rate" action in the card without needing to open the full edit dialog.

## Build Order Rationale

1. **Dead-code cleanup first** — removes confusion about what's real schema, no regressions possible
2. **Dashboard charts second** — high visibility, simple to implement, no backend work
3. **GST Invoice PDF third** — operationally needed but can use workarounds (screenshot, detail dialog) in the meantime
4. **Polish last** — driven by real usage feedback, not speculative
